A Claude Code mod · first run 5 October 2026

LLM answers change every time. A seed makes one repeat.

In pandas or numpy, a seed makes random results come out the same on every run. This mod gives LLM answers the same property: pick a seed, and the answer to a question is fixed for that seed.

Same seedand the same question return the identical answer, word for word
New seedreturns a fresh answer to the same question
One fileper answer, saved with the project so a colleague gets the same result

Why it is needed

"The AI told me this" is hard for anyone else to check. A screenshot can be edited. A chat link shows the model said something once, but nobody can rerun it, its owner can delete it, and many company accounts block sharing.

ProblemTodayWith a seed
An AI answer nobody else can checkA screenshot or a chat linkA seed and a question a colleague reruns to get the same words

A result in a report that cannot be reproducedNothingThe answer is stored with the project, with the time it was drawn

How it works

The mod does not change how the model picks its words. Chat tools give no control over that. It works one level up: the first answer drawn for a seed is pinned to that seed.

  1. You ask with /seed, a seed and a question.
  2. A key is built from the model name, the seed and the exact question.
  3. No saved answer? The model is asked once, and the answer is saved under that key.
  4. Saved answer? Its fingerprint is checked and it is returned. The model is not asked.

Each saved answer is one small, readable file in a seeds folder inside the project:

{
  "seed": "42",
  "question": "Write a one-line slogan for an AI analytics team.",
  "model": "haiku",
  "answer": "\"Turning data into decisions, one insight at a time.\"",
  "drawnAt": "2026-10-05T16:53:28.855Z",
  "sha256": "f3b787d2e728..."
}

Questions

Does this make the model deterministic?

No. The model is as random as before. The seed makes the result repeatable by fixing the first answer drawn for that seed. Ask the same question without /seed and you still get a different answer each time.

So is it a cache?

Yes, with three differences that matter. You choose the seed, so you can ask for a new draw on purpose. The saved answers are plain files that travel with the project, so other people get the same results. And each one carries the time it was drawn and a fingerprint.

Why not use a real seed?

Where a model's developer interface offers a seed setting, it is described as best effort: the same seed usually gives the same output, not always, and it can change when the provider updates the model. Chat tools do not expose it at all. Saving the answer is the only way to get an exact match every time.

What does the seed number mean?

Nothing by itself. It is a label. 42, 7 and demo-day all work.

Is seed 42 the same answer for everyone?

Only for people who share the seeds folder. Commit that folder to git with the project, tell a colleague the seed and the question, and they get your answer.

Can someone fake an answer?

The fingerprint catches a saved answer that was edited afterwards. It does not stop someone who rewrites both the answer and the fingerprint. For that, git history shows who changed the file and when. This is evidence, not cryptographic proof.

How do I get a new answer for the same question?

Use a different seed, or delete that answer's file in the seeds folder.

Does a replay cost anything?

No. A replay reads a file. Only a first draw calls the model.

Which model answers?

Claude Haiku, a small and fast model, so it may not know niche facts. Another model is a one-line change. The model name is part of the key, so answers from different models never mix.

Is my question private?

No. The question and the answer are saved as plain text. If the folder is pushed to a public repository, everyone can read them.

Does something like this already exist?

In parts. Developer tools cache model calls, and some model interfaces have a best-effort seed setting. This puts the idea where the work happens, as one command, with answers shared through the project.

What this does and does not do

  • The model is still random. Only the result for a seed is fixed.
  • A saved answer is one draw. It shows what the model said once, not what it usually says. Try several seeds to see the spread.
  • The question must match exactly. A reworded question is a new question.
  • Text in, text out. No files, images, web search or chat history are sent with the question.
  • It needs a Claude Code version that supports mods, which are a new feature.

Try it

Get the code from github.com/eshwarpotturi/llm-seed, start Claude Code with the mod loaded, then send one line at a time.

claude --plugin-dir /path/to/llm-seed
